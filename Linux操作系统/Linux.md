### 基础知识

- 先理解 Linux 如何支撑一个服务 一次请求进入服务器，大致会经过
 ```
网卡接收数据
  → 内核网络协议栈
  → Socket 接收队列
  → 应用线程获得 CPU
  → 读取内存、文件或调用下游
  → 返回响应
```

任何一环排队，都可能导致响应变慢。SRE 需要掌握以下基础：

| 知识 | 必须理解的内容 | 对排障的帮助 |
|---|---|---|
| 用户态与内核态 | 应用通过系统调用访问内核功能 | 区分计算开销与系统调用开销 |
| 进程与线程 | 地址空间、线程共享资源、调度和信号 | 定位热点线程、死锁及异常退出 |
| 虚拟内存 | 匿名页、文件页、缺页、回收、Swap | 分析内存增长、抖动和 OOM |
| 文件系统 | 文件描述符、inode、目录项、页缓存 | 分析空间不足、文件泄漏和写入延迟 |
| 网络 | TCP 状态、连接队列、重传、路由、DNS | 分析连接失败和请求超时 |
| 资源隔离 | namespace、cgroup | 解释容器内外指标为何不同 |
| 服务管理 | systemd、日志、启动依赖、资源限制 | 分析服务启动失败和反复重启 |

/proc 提供进程和内核运行信息，/sys 提供设备及内核子系统信息。它们是许多监控命令的数据来源。

- 建立统一的排障顺序
  - 先确定业务影响，再检查资源，最后深入到进程和代码：
    - 延迟、错误率、吞吐量是否异常
    - 哪些实例、接口、时间段受影响
    - 是否发生发布、配置或流量变化
    - CPU、内存、磁盘、网络哪里出现等待或错误
    - 哪个进程、线程、系统调用导致问题

| 维度 | 要回答的问题 | 示例 |
|---|---|---|
| 使用率 | 已使用多少资源？ | CPU 使用率、磁盘吞吐量 |
| 饱和度 | 是否出现排队或等待？ | 运行队列、I/O 队列、资源压力 |
| 错误 | 是否出现失败？ | OOM、磁盘错误、网络丢包 |

 ```
# 查看每个逻辑 CPU
mpstat -P ALL 1 5

# 查看进程 CPU、上下文切换
pidstat -u -w 1 5

# 查看指定进程的线程
top -H -p 1234

# 查看进程状态和等待位置
ps -eo pid,ppid,stat,pcpu,pmem,wchan:28,comm --sort=-pcpu | head -20
```
